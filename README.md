# Детекция угроз для БПЛА: модели по угрозам

Каждая угроза из списка закрывается отдельным ноутбуком; общий код вынесен в `src/`.

## Структура
```
src/
  physics.py        Td (Magnus), Tw (Stull), RH, высотный профиль
  detectors.py      гистерезис, CUSUM, лаг-фильтр
  metrics.py        задержка/событийные метрики, ECE, reliability
  alerts.py         Gate: гистерезис, подтверждение n подряд, пауза после отбоя
  detectors_bvs5.py онлайн-детекторы БВС-5/НСУ-3 (CondensationV2, потоковые признаки, ConditionDetector)
  eval_bvs5.py      кэш сценариев и событийные метрики для этих детекторов
  detectors_bvs4.py признаки БВС-4 (подтверждение, окно, контекст), Condition4Detector, BlindnessMonitor
  eval_bvs4.py      кэш сценариев с БВС-4, метки, истина слепоты
  detectors_power.py остаток мощности, град, перегрев cpu_temp
  eval_power.py     лёгкий кэш сценариев и событийная оценка для них
  detectors_vis.py  признаки видимости (дальности первого обнаружения), физическая оценка по сенсорам
  eval_vis.py       метрики по диапазонам видимости, событийная оценка «V < порога»
  streams.py        генератор потоков БВС-1/2/4/5/7, НСУ-2/3, сетевая модель, шина (по ТЗ)
  harness.py        стенд: прогон детекторов, время обработки, задержка, ложные тревоги + эталонные детекторы
  synth_fog.py      синтетический сценарий запотевания (физика линзы + кадры + датчики БВС-5)
  fog_detectors.py  физический и видео-детекторы, слияние, Monte-Carlo оценка
  data_metar.py     загрузка METAR (Iowa Mesonet), разметка классов, запасной синтетический ряд
  synth_light.py    синтетическая камера: автоэкспозиция, шум, ореол, лазер/огни/огонь/блик + тепловизор
  light_features.py признаки кадра (насыщение, шум по Иммеркеру, ореол, тепловой избыток), высота Солнца
  light_detectors.py правила R0-R3 для лазера, Isolation Forest/PCA, RGB-кандидаты очагов
  light_eval.py     генерация выборок и оценка детекторов (угроза 10)
  synth_aerosol.py  физическая модель дымки/пыли/шлейфа/фронта (RGB, тепловизор, LiDAR), наклонная геометрия
  aerosol_est.py    тёмный канал, LiDAR (Бугер-Ламберт), спектр/ЛВИК, анализ шлейфа, правило классов
  aerosol_eval.py   выборки сценариев, признаки, таблицы для оценки
notebooks/
  00_streams_testbench.ipynb  ГЕНЕРАТОР ПОТОКОВ по «Потоки_данных.pdf» + стенд замера задержек (основа нового плана)
  01_bvs5_condition_detectors.ipynb  онлайн-детекторы на БВС-5/НСУ-3: конденсат (28) + метео-классификатор (5, 7, 8, 9), подавление повторов
  02_bvs4_fusion_blindness.ipynb  БВС-4: перекрёстное подтверждение lidar/radar/camera, причины помех, слепота сенсоров
  03_power_stability.ipynb    мощность и устойчивость: налипание/намокание, град (attitude+IMU+прогноз), перегрев от пыли
  04_visibility_fusion.ipynb  слияние видимости: НСУ-3 + БВС-4 (дальности, фантомы) + БВС-5; доверие сенсорам; смена условий
  legacy/                     старые ноутбуки 01-05 (видео-версии; справочные, будут переписаны под потоки ТЗ)
  _template.ipynb             шаблон ноутбука (разделы 1-9)
  01_condensation.ipynb       угроза 28: конденсат/роса
  02_precip_classifier.ipynb  угрозы 7, 8, 9, 5: тип погоды по T/RH/ветру (реальные метки METAR)
  03_light_threats.ipynb      угрозы 10 и 16: лазер/прожекторы, световое загрязнение (всё синтетика)
  04_aerosol_visibility.ipynb угрозы 1, 14, 15: оценка видимости, тип аэрозоля, шлейф vs мгла vs пылевой фронт (синтетика)
data/               кэш загрузок (CSV), в git не добавлять
reports/            графики/таблицы для отчёта
```

## Запуск
```
pip install -r requirements.txt
jupyter lab            # открыть notebooks/ и выполнить сверху вниз
```
Ноутбуки сами находят `src/` (запускать из `notebooks/` или из корня).

## Важно
* Ноутбук 02 пытается скачать METAR с mesonet.agron.iastate.edu. Без сети он **выводит предупреждение** и подставляет
  синтетический ряд (метки порождены правилами): тогда цифры нельзя использовать в отчёте.
* Ноутбук 01 целиком синтетический: это проверка метода на известной «истине», а не оценка точности на борту.
* Тесты и запуск кода выполнялись в окружении без доступа в интернет; загрузка IEM на реальных данных
  не проверялась (при ошибке формата смотрите `src/data_metar.py: download_iem / hourly_table`).
* Ноутбук 03 целиком синтетический (одноканальный кадр, идеальная регистрация RGB/тепловизор); время выполнения
  несколько минут. Метаданные усиления/экспозиции ISP считаются доступными (уточнить у заказчика).
* Ноутбук 04 синтетический (параметры типов аэрозоля заданы по порядку величины); выполняется около 2 минут.

## ВАЖНО: переход на план по потокам ТЗ
В ТЗ нет видеопотока, сырого IMU и сырых данных lidar/radar. Ноутбуки 01-02 применимы
(физика конденсата и метео-классификатор по БВС-5 / НСУ-3). Ноутбуки 03-05 построены на видео (и на сырых данных
lidar/IMU) и сохранены лишь как справочные: они будут переписаны на поля БВС-4/5/7 и НСУ-2/3.
Новые детекторы пишутся под интерфейс `Detector` из `src/harness.py` и проверяются на стенде ноутбука 00.
